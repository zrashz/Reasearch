# GPU development candidate workflow

Use a Colab GPU runtime. Keep the original Drive project. Open 04_GPU_DEVELOPMENT.ipynb, run the cells in order, and upload Scientific_News_GPU_Development_Update.zip at the install cell. Do not rerun the older CPU package-install cells. This package does not install or replace torch/transformers automatically. It checks that the needed classes and CUDA are available first. GPU availability is controlled by Colab and is not guaranteed.

The new writer is Qwen/Qwen2.5-VL-3B-Instruct. Its exact Hub revision is resolved once and persisted under private/model_pins/gpu_vlm_candidate_v1.json before loading. The current environment versions, dtype, image budget and source/code hashes are logged. The inference code follows the official model card's Qwen2_5_VLForConditionalGeneration plus AutoProcessor interface, uses actual PIL images with the processor, SDPA attention and GPU float16 on T4 (bfloat16 only if supported). qwen-vl-utils/video packages are not needed for this still-image path.

The writer returns structured JSON objects containing statements and evidence ID arrays. A complete outer Markdown fence can be removed, but trailing commentary, invalid fields and more than four statements are rejected. The old anchor-punctuation parser is not used by this backend. This is a format improvement, not a factuality guarantee.

The existing V0–V3 controller is reused: V0/V2 share raw drafts; V1/V3 share prechecked drafts; one correction opportunity per claim per enabled stage; unresolved claims withheld; no length padding. E1/E2/E3 original prefix and image/source byte hashes are checked. Only whole evidence records are retrieved; exclusions are logged. Retrieval is results-first lexical development selection, not the proposal's final frozen embedding configuration. News titles guide relevance only and are not paper evidence.

Verification is conservative and incomplete. Exact complete source sentences can receive provisional textual support (not positive substrings inside negated sentences). Other numerical claims require the installed source-specific MAD adapter; unresolved numerical scope is withheld. Textual entailment uses the previous DeBERTa-small with an uncalibrated 0.9 development threshold. Nonnumerical table/image claims can receive tentative VLM decisions. The same VLM generates and visually verifies, so errors are correlated; those decisions are not independent annotations or calibrated scientific approvals. All outputs retain automatic_scientific_approval=false. Arbitrary table arithmetic and visual numerical extraction are not solved by this package. Independent evaluation and finding inventories remain required.

Use one paper, E2 first to compare the writer with the prior failed CPU candidate. The notebook includes an optional separate batch cell for the 15 prepared studies and all three conditions. Do not run that batch until the first GPU output is reviewed. Cases used for live runs are explicitly recorded as development exposures; provide that list to the existing split-preparation tool later. Never move inspected development output into the final test set.

Validation: 12 new offline tests and 95 combined project tests pass. Audit-only CLI exercised actual source XML with reconstructed evidence/image-byte fixtures. GPU inference was not performed in the artifact-building environment. The first Colab execution must validate hardware/library compatibility, memory use and actual output quality. A model run may still fail or produce weak summaries; preserved events support diagnosis without overwriting previous work.

References: https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct and https://research.google.com/colaboratory/faq.html
